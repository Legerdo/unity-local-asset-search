# 0.2.2 오디오·통합 검색 원인 점검과 개선

2026-10-28. 원본 복제 없이 AnimationFramework 실제 자료 192개(문서·이미지·오디오 각각 64개)로 진단·전후 비교·제품 코드 재검증을 수행했습니다. 이번 표본은 426벡터이며 앞선 539벡터 표본과 다릅니다. 이번 진단 매니페스트를 고정하고 전후/최종 실행의 192개 SHA-256 목록이 동일함을 확인했습니다. 과거 수치와 직접 A/B 비교하지 않았습니다.

## 원인 판정

- [공식 모델 카드](https://huggingface.co/google/embeddinggemma-2#best-practices)의 16kHz 모노 입력, BF16, 검색어 프롬프트를 확인했습니다. 현재 설정과 일치합니다.
- 오디오 64개의 첫 청크를 단독/배치로 비교한 최소 코사인은 0.999102였습니다. 8개의 짧은 오디오를 파일 경로로 직접 입력한 경우와 현재 배열 전처리의 코사인은 모두 약 1.0이었습니다. 이번 표본에서 전처리 경로 오류나 큰 배치 왜곡은 검출하지 못했습니다.
- 18개 동일 질의의 API 상위 5개 순위가 DB 벡터를 독립적으로 내적해 계산한 순위와 전부 일치했습니다. 정렬·중복 청크 집계 오류도 검출하지 못했습니다.
- 기존 설계는 텍스트에만 제목을 제공하고 이미지·오디오에는 파형/픽셀만 넣었습니다. 짧은 타격음·진동 표본·기술 텍스처는 콘텐츠만으로 개발자의 에셋 의도를 설명하기 어렵습니다. 이는 이번 모델/도메인 조합의 한계와 메타데이터를 누락한 검색 설계가 함께 드러난 결과입니다. 모델 가중치 자체의 결함으로 확정한 것은 아닙니다. FP32 비교나 별도 정답 오디오 데이터셋 평가는 수행하지 않았습니다.

## 변경

이미지·오디오의 실제 콘텐츠와 읽기 쉬운 파일명 및 가까운 두 폴더 이름을 단일 복합 입력으로 임베딩합니다. 제목 160자·폴더 240자로 제한하고 절대 경로는 넣지 않습니다. 원본 파형/픽셀 전처리, 768차원, 코사인 점수, 필터와 정렬 API는 유지합니다. 점수 가산이나 특정 파일 우대 규칙은 없습니다.

공식 모델이 지원하는 복합 입력을 사용했습니다. 변경된 것은 모델의 순수 소리 인식 능력이 아니라 **메타데이터를 함께 사용하는 에셋 검색**입니다. 부정확한 이름·폴더는 결과를 왜곡할 수 있습니다. 이름이 무의미하거나 소리 자체의 의미만 찾아야 하는 경우에는 한계가 남습니다.

전처리 지문을 v3-media-context-v1로 갱신했습니다. **이전 생성 인덱스는 설정 탭에서 초기화 후 재색인이 필요합니다.** 기존 인덱스를 자동 삭제하거나 이전 벡터와 혼합하지 않습니다.

## 같은 자료·같은 질의의 통합 검색 비교

질의 30개: 원래 표현 18개와 개선 결과를 보기 전에 준비한 바꿔 쓴 표현 12개. 아래는 사전 지정한 파일이 상위 5개에 포함된 건수입니다. 참조 파일이 없는 질의 1개는 표의 분모에서 제외하되 원시 결과에는 보존했습니다.

| 종류 | 질의 묶음 | 변경 전 | 최종 제품 코드 |
|---|---|---:|---:|
| audio | 원래 표현 | 1/6 | 6/6 |
| audio | 추가 표현 | 1/6 | 6/6 |
| image | 원래 표현 | 2/6 | 6/6 |
| image | 추가 표현 | 1/4 | 3/4 |
| text | 원래 표현 | 4/5 | 4/5 |
| text | 추가 표현 | 2/2 | 2/2 |

참조는 파일명에서 정한 약한 라벨입니다. 다른 자료도 정답일 수 있고, 모든 오디오를 청취해 정답을 확정하지 않았습니다. 따라서 표는 회귀/참조 포함 검사이며 정식 Recall@5나 실제 정답률이 아닙니다. 최상위가 항상 맞는 것도 아닙니다. 얼굴 색상 텍스처 질의에 얼굴 노멀맵이 먼저 나온 예처럼 세부 구분의 한계가 남았습니다.

## 최종 제품 코드 검증

- 실제 192개 색인 성공, 실패 0개, 426개 벡터 생성. 변경 없는 재색인은 192개 모두 건너뜁니다.
- 색인 14.56초. 전체 종류의 새 검색어 HTTP 응답 중앙값 46.33ms, P95 58.85ms. UI 표시 시간은 제외됩니다. 별도 성능 질의에는 Find assets matching: 접두어가 있으며, 위 품질 비교는 같은 원문 질의를 사용했습니다.
- 원본 192개 SHA-256 재검사 통과. 각 실행의 임시 인덱스·상태 폴더 삭제 확인. 실제 리소스나 모델을 패키지/Git에 추가하지 않았습니다.
- 회귀 검사: 변경 전에는 미디어 제목 부재로 실패했고, 변경 후에는 제목/상대 폴더가 포함되면서 파형 샘플과 픽셀이 보존되는지 검사해 통과했습니다.
- Backend 19개 + Agent 2개, 총 21개 자동 검사와 101개 로케일 키/UXML 패키지 검사 통과. C#·UI 코드는 변경하지 않았고 이번에 Unity UI 재검증은 수행하지 않았습니다.

실행 게이트: `python -m unittest discover -s Backend~ -p test_*.py -v`, `python -m unittest discover -s Agent~ -p test_*.py -v`, `python Backend~/validate_package.py`, `git diff --check`. 실제 모델 검증은 별도 테스트 스크립트에서 제품 HTTP 핸들러/Engine을 호출했습니다. 재현 스크립트는 결과 JSON에 포함합니다.
